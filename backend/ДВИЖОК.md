# Документация движка «Собачьи тёрки» (бэкенд)

Справочник по игровому движку. Предназначен, чтобы **новый агент мог работать с методами
движка, не читая весь код**: здесь перечислены модели, команды, функции, инварианты и
способы тестирования. Пути — относительно `web/backend/`.

---

## 1. Архитектура

- **Сервер-авторитетный** движок: клиент шлёт «намерения» (команды), сервер валидирует,
  применяет и возвращает новый снапшот. Никакой игровой логики на клиенте.
- **Снапшот** — весь `GameState` (Pydantic-модель), сериализуется в JSON и лежит в таблице
  `games` (колонка `state`). Снапшот самодостаточен (колоды, районы, рёбра денормализованы).
- **Командный паттерн**: `AnyCommand` (дискриминируемый union по полю `type`) → каждая команда
  имеет `validate(state)` и `apply(state, rng)`.
- **Цикл движка** (`engine.GameEngine.dispatch`):
  `load → validate → apply(deep copy) → version+1 / rng_state → save (CAS)`.
- **Детерминированный ГСЧ** (`rng.Rng`): состояние хранится в `GameState.rng_state`,
  восстанавливается `Rng.from_state` перед каждой командой и сохраняется после.
- **Логика чистая**: доменные модули (`state`, `resources`, `combat`, `buildings`, …) работают
  без БД. БД (SQLAlchemy) нужна только в `store`, `models`, `routers`, `seed`.

### Стек
Python 3.11+, Pydantic v2, SQLAlchemy 2.0 async (по умолчанию SQLite `sqlite+aiosqlite`,
Postgres через `DATABASE_URL`), FastAPI. Фронтенд (Vue 2) пока не реализован.

### Структура `app/`

## 2. Модель состояния (`state.py`)

`GameState` — корневой снапшот. Ниже — все поля и вложенные модели.

### Фазы `Phase` (str Enum)
`SETUP` → `DRAFT` → `PLAY` → `END_ROUND` → `FINISHED`.

### `PlayerState`
| Поле | Тип | Смысл |
|---|---|---|
| `seat` | int | место 0..N-1 |
| `money` | int = 1500 | деньги |
| `hand` | list[str] | id карт действий |
| `explosives` | int = 1 | взрывчатка в запасе |
| `kompromat` | list[int] | жетоны компромата; значение = **целевой seat** |
| `authority_line` | list[str] | 6 ключей жетонов авторитета (см. `tokens.AUTHORITY_TOKENS`) |
| `combat_line` | list[str] | 6 ключей боевых жетонов (см. `tokens.COMBAT_TOKENS`) |
| `victory_points` | int = 0 | ПО (6 = победа) |
| `used_abilities` | list[int] | районы, чьё свойство уже использовано в этот ход |

### `DistrictState` (ключ в `GameState.districts` — номер гекса 1..13)
| Поле | Тип | Смысл |
|---|---|---|
| `id` | int | номер гекса |
| `building_owner` | int\|None | seat владельца здания (None — пусто) |
| `dogs` | dict[int,int] | seat → число псов |
| `mangy` | int | число шелудивых |
| `kompromat` | list[int] | чьи жетоны компромата лежат здесь (target seats) |
| `explosives` | list[dict] | `[{"owner": seat, "active": bool}]` |
| `money` | int | деньги, лежащие в районе |
| `build_cost` | int | цена постройки (из каталога) |
| `income` | int | доход владельцу за ход |
| `ability` | dict\|None | свойство района: `{"kind": ..., ...}` |

### `CombatState`
`district_id`, `attacker`, `defender` (None = бой с шелудивыми), `next_is_attacker` (чей ход),
`pending` (`{"face": int, "opposite": int}` — бросок в ожидании переворота),
`mangy_killed_or_recruited` (счётчик для условия влияния).

### `GameState` (основные поля)
`id` (uuid), `player_count`, `seed`, `rng_state`, `version`, `round`, `phase`,
`first_seat`, `current_seat`, `passes_in_a_row`, `draft`, `combat`, `last_combat`,
`winners`, `board_districts` (активные гексы 1..7/10/13), `cards` (id→{standard_key, situational_key}),
`edges` (`[{a,b,kind}]`, kind=land|river), `debtors` (для «Кредита»),
`pending_reaction` (окно реакции), `influence_bag` (40 наградных жетонов),
`pending_influence` (очередь `{seat, token}` для обмена), `players`, `districts`,
`action_deck`, `event_deck` (`DeckState{draw, discard}`), `broken_bridges` (пары [a,b]).

### `new_game(player_count, seed=0) -> GameState`
Базовая подготовка: деньги 1500, взрывчатка 1, компромат-на-себя 1, стартовые 200$ в
районы 1,2,3,8,11. Колоды и драфт собирает `round.prepare_game`.

## 3. Команды (`commands.py`)

Все команды наследуют `Command` (поле `seat`) и имеют `type` (строковый литерал).
`AnyCommand` — union по `type`. Движок вызывает `validate` затем `apply`.

| Команда | `type` | Ключевые поля | Что делает |
|---|---|---|---|
| `PassCommand` | `pass` | — | пас; все спасовали → `end_round` |
| `PickDraftCardCommand` | `pick_draft` | `card_id` | выбор карты в драфте |
| `PlayCardCommand` | `play_card` | `card_id`, `option`, `district_id`, `amount`, `target_seat`, `defender`, `active`, `resource`, `to_district`, `dogs_count`, `mangy_count` | сыграть карту: стандартное действие + доход + сброс |
| `PlayKompromatCommand` | `play_kompromat` | `district_id`, `card_id`, `move_to`, `property_district`, `target_seat`, `buy_discard`, `target_district` | сыграть компромат: бросок авторитета + доход + эффект жетона (+белый жетон→свойство) |
| `ChooseInfluenceTokenCommand` | `choose_influence` | `swap_slot` (0..5 \| None) | положить вытянутый жетон влияния в слот или сразу ПО |
| `UseAbilityCommand` | `use_ability` | `district_id`, `target_seat`, `buy_discard`, `target_district` | свойство своего здания (раз в ход) |
| `PlaySituationalCommand` | `play_situational` | `action`, `card_id` (None→компромат) | сыграть ситуативное действие в окне реакции |
| `PassReactionCommand` | `pass_reaction` | — | пропустить окно реакции |
| `StartCombatCommand` | `start_combat` | `district_id`, `defender` | начать бой (может открыть окно first_strike) |
| `RollCombatDieCommand` | `roll_combat` | — | бросок текущей стороны в бою |
| `ResolveCombatRollCommand` | `resolve_combat` | `flip`, `reroll`, `move_seat`, `move_to` | применить бросок (flip=переворот за компромат, reroll=переброс) |
| `AdvancePhaseCommand` | `advance_phase` | — | служебная: сдвинуть фазу (для тестов) |

**Важно о командах:** `apply` работает с ПЕРЕДАННОЙ глубокой копией и **не трогает**
`version` и `rng_state` — их обновляет `engine.dispatch`. Все ошибки — `CommandError`.

## 4. Ключевые модули и функции (сигнатуры)

### `rng.py`
`Rng(seed=None)`, `Rng.from_state(state)`, `rng.state() -> list`,
`roll(sides=6) -> int` (0..sides-1), `roll_d6() -> int` (1..6),
`shuffle(seq)`, `choice(seq)`, `sample(seq, k)`, `draw_bag(bag, k)`.

### `round.py`
- `prepare_game(n, seed, action_cards, event_cards, districts, hex_edges) -> GameState` — полная сборка партии (колоды, тасовка, влияние-мешок, первый драфт).
- `start_round(state, rng)` — раздача драфта.
- `advance_draft(state, rng)` — передать/сбросить карты драфта.
- `end_round(state, rng)` — разбор полётов: влияние → событие → сброс рук → победа → компромат → новый раунд.
- `next_turn(state)` — передать ход + сбросить `used_abilities`.

### `board.py`
- `is_passable(state, a, b)`, `neighbors(state, district_id)`, `is_bridge`, `is_broken`.
- `validate_move(state, seat, from, to, dogs_count, mangy_count)` (чистая проверка).
- `move(state, seat, from, to, dogs_count, mangy_count)`.
- `destroy_bridge(state, seat, a, b)` (взрывчатка), `repair_bridge(state, seat, a, b)` (500$).

### `resources.py`
- `take_money(state, seat, district_id)`, `place_money(state, seat, district_id, amount)`.
- `lift_kompromat_self(state, rng, seat, district_id)` (проверка авторитета ≥5).
- `take_kompromat_other(state, seat, district_id, target_seat)`, `place_kompromat(...)`.
- `mine(state, seat, district_id, active=True)`, `take_explosive(...)`, `demine(...)`.
- `explode(state, rng, district_id, owner=0)` — взрыв (бросок владельца; гибель = грань атаки **или** чёрная грань; броник спасает через окно реакции).
- `resume_explosion(state, rng, pending)` — продолжение взрыва после окна броника.

### `combat.py`
- `validate_start(state, attacker, district_id, defender)`, `start_combat(...)`.
- `roll_combat(state, rng)` — бросок (для игрока кладёт `pending`).
- `resolve_roll(state, rng, flip, move_seat, move_to)` — применить бросок.
- `resume_combat_roll(state, rng)` — продолжить после окна броника.
- `_finish(state, rng, winner)` — завершение боя: влияние → событие → окно субсидии/уборки.

### `buildings.py`
- `controller(state, district_id) -> seat|None` (контроль: твоих фишек строго больше всех).
- `build(state, seat, district_id)`, `destroy_building(state, rng, seat, district_id)`.
- `collect_income(state, seat) -> int` — доход со всех твоих зданий.
- `use_ability(state, rng, seat, district_id, target_seat, buy_discard, target_district)`.

### `influence.py`
- `gain_influence(state, seat, amount=1)` — тянет жетон из мешка + ПО + кладёт в `pending_influence`.
- `check_win(state) -> bool` — 6 ПО → `FINISHED` + `winners`.
- `influence_for_build/destroy/combat(state, ...)`, `end_round_influence(state)`.
- `control_score`, `network_score`, `apply_penalty`, `distribute_kompromat`.

### `actions.py`
`resolve_standard(state, rng, seat, standard_key, option, district_id, amount, target_seat,
defender, active, resource, to_district, dogs_count, mangy_count)` — диспетчер по `standard_key`.
`add_mangy`, `recruit_mangy`.

### `events.py`
`draw_event(state, rng) -> slug|None`, `draw_and_resolve_event(state, rng, actor_seat)`,
`resolve_event(state, rng, slug, actor_seat)`.

### `reactions.py`
`TRIGGER_ACTIONS` (триггер→допустимые ситуативные действия), `eligible`, `next_responder`,
`try_open`, `open_combat_started`, `open_moved_into`, `open_dog_killed`, `open_combat_ended`,
`open_influence_gained`, `play`, `pass_reaction`, `close`, `has_situational`, `spend_situational`.

### `tokens.py`
`COMBAT_TOKENS` (10: 6 стартовых + 4 наградных), `AUTHORITY_TOKENS` (10), `build_influence_bag()`,
`is_combat_token`, `authority_value(state, seat, face)`, `authority_check(state, rng, seat)`,
`is_black_face`, `is_white_face`, `combat_effect`, `is_explosion_death_face`.

### `authority.py`
`apply_effect(state, rng, seat, effect, district_id, card_id, move_to)` — эффект жетона авторитета.

### `engine.py` / `store.py`
`GameEngine.dispatch(game_id, command) -> GameState` (async).
`GameStore.create/load/save(state)` (async; save — CAS, бросает `VersionConflict`).

## 5. Ключевые правила-инварианты

- **Seat** — целое 0..N-1. **N** = `player_count` (2, 3 или 4).
- **Кубик один**, 6 мастей (грани `0..5`). Грань → слот на планшете.
  - Боевой слот → боевой жетон (эффект). **«Чёрная грань»** = в слоте **наградной** боевой жетон (`is_black_face`).
  - Авторитетный слот → жетон авторитета (значение). **«Белый жетон»** = наградной жетон авторитета (`is_white_face`).
  - **Проверка авторитета** = числовое значение жетона (`authority_check`), НЕ `roll_d6()`.
- **Влияние** = вытянуть жетон из `influence_bag` + 1 ПО + очередь `pending_influence` (клиент
  решает `choose_influence` — в слот или сразу ПО).
- **Компромат** хранится как список **целевых** seat: в `PlayerState.kompromat` (на руках) и
  `DistrictState.kompromat` (в районе). «Компромат на себя» = элемент == своему seat.
- **Победа** — 6 ПО (`VICTORY_POINTS_TO_WIN`).
- **Контроль района** — `buildings.controller`: твоих фишек (псы + здание) строго больше, чем
  у каждого другого игрока и больше числа шелудивых.
- **Окно реакции** (`pending_reaction`) ставит паузу; игроки отвечают `play_situational` /
  `pass_reaction`; когда все подходящие ответили — `close` применяет отложенный эффект.
  Триггеры: `combat_started` (first_strike), `moved_into` (ambush/no_entry/detonate),
  `dog_killed` (armor), `combat_ended` (cleanup), `influence_gained` (subsidy).
- **Взрыв** (`resources.explode`): бросает **владелец** взрывчатки; гибель = грань атаки
  (`combat_effect == "attack"`) ИЛИ чёрная грань. Спасение — броник (окно `dog_killed`,
  `resume="explosion"`).
- **Стандартные действия** (`standard_key`): `lift_place`, `summon_recruit`, `move`,
  `start_fight`, `build_destroy`. Поддействия передаются через `option` (см. `action_definitions.json`).
- **Ситуативные действия** (`situational_key`, 8 шт.): `ambush`, `first_strike`, `subsidy`,
  `cleanup`, `reroll`, `armor`, `no_entry`, `detonate`.

## 7. Жизненный цикл

1. **Подготовка**: `POST /api/games` → `round.prepare_game` → фаза `DRAFT`.
2. **Драфт**: 2 сделки × 4 карты, одновременный выбор (`pick_draft`).
3. **Розыгрыш** (`PLAY`): по кругу `play_card` / `play_kompromat` / `pass`.
   - Розыгрыш карты: стандартное действие → доход → сброс → проверка победы → (если получено
     влияние: окно субсидии + событие) → передача хода.
   - **Бой**: `start_combat` → по очереди `roll_combat`/`resolve_combat` → `_finish`.
   - **Окна реакции** и **очередь обмена жетонов** (`pending_influence`) — клиент должен их
     разрешать соответствующими командами, пока поле не пустое.
4. **Конец раунда**: все спасовали → `end_round` (влияние «Контроль»/«Сеть» → штраф → событие →
   сброс рук → проверка победы → компромат отстающим → новый раунд).
5. **Победа**: 6 ПО → `FINISHED`, `winners`.

## 8. HTTP API (`routers/`)

- `POST /api/games` — создать партию (body: `{player_count, seed}`), возвращает `GameState`.
- `GET /api/games/{id}` — снапшот.
- `POST /api/games/{id}/commands` — отправить команду (body = сериализованный `AnyCommand`),
  возвращает новый `GameState`. Ошибки: 404 (не найдена), 409 (`CommandError` или `VersionConflict`).
- Каталоги: `/api/catalog/*`, `/api/board/*` (см. `routers/catalog.py`, `routers/board.py`).

## 9. Как тестировать (без БД)

Логика чистая — тестируется прямыми вызовами:

```python
from app.state import new_game, Phase, CombatState
from app.rng import Rng
from app import resources, tokens, influence
from app.commands import PlayCardCommand

s = new_game(2, seed=0)          # базовое состояние (без колод)
# ... настроить s (районы, псов, карты) ...
resources.explode(s, Rng(0), 1, owner=0)

cmd = PlayCardCommand(seat=0, card_id="10", ...)
cmd.validate(s)                                     # бросает CommandError при нелегальности
new = cmd.apply(s.model_copy(deep=True), Rng(0))    # чистая мутация копии
```

Для полного цикла (колоды, драфт) нужен `round.prepare_game` с каталогами из БД — см. тесты
из истории (seed + `prepare_game`). Установка зависимостей: `pip install --target web\_deps
"sqlalchemy[asyncio]" aiosqlite fastapi uvicorn asyncpg`, затем `python -m app.seed`.

## 10. Конвенции и предостережения

- **UTF-8 без BOM** для всех файлов (запись — `[System.IO.File]::WriteAllText` с
  `UTF8Encoding($false)`; `Set-Content -Encoding utf8` добавляет BOM — не использовать).
- Весь текст и комментарии — **на русском**.
- `apply`/функции-мутации мутируют **переданный** объект (движок передаёт глубокую копию);
  ничего не возвращают, кроме `GameState` в командах.
- `validate` — чистая проверка без мутаций; все нарушения — `CommandError`.
- В `apply` НЕ трогать `version` и `rng_state` (движок делает сам).
- Линии жетонов (`authority_line`/`combat_line`) — **ключи**, значения в `tokens.*_TOKENS`.
- `passes_in_a_row >= player_count` → `end_round`.
- Рёбра реки (`kind=="river"`) — это мосты; сломанные — в `broken_bridges` (канонические
  отсортированные пары [a,b]).

## 11. Известные упрощения / отложенное (не реализовано)

- **Казино**: переброс за +1$ к ставке (реализован простой максимум авторитета).
- **Русская рулетка**: убирается «первый попавшийся» пёс (нет выбора).
- **Радиостанция** `peek_events`: заглушка (бросает CommandError).
- **no_entry**: только «остаться на месте» (вариант «в другой соседний район» нет).
- **reroll**: только боевой кубик (кубик авторитета не перебрасывается).
- **swap_card / swap_card_better**: вторая половина «поменять жетон влияния на случайный из
  мешка» не реализована (только смена карты).
- **extract**: приоритет «компромат из района → из руки → 200$» (выбор игрока не спрашивается).
- **Интерактивные события** (no-op, нужны команды-выборы): «Кредит», «Чёрный рынок компромата»,
  «Субботник», «Чёрная пятница», «Строительный бум».
- **Setup**: выбор логова, порядок жетонов боя «в любом порядке», мешочек жетонов районов.
- **Банды** (асимметрия) — `gangs.json` есть, способности не подключены.
- **Сеть/лобби, WebSocket, Redis, фронтенд (Vue 2)** — часть 2, не начаты.
